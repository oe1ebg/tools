    Loading

    Drag .adi or .adx files onto the page, or use "add file(s)…". Files are added to the current log; "new" starts an empty one, "clear…" removes the whole log from the editor. Nothing leaves the browser.

    "single file ↓" saves the whole editor as one HTML file that works without a server and without internet.

    Editing

    Enter
    take the value and go one row down
    Esc
    restore the value from before the edit (in a list of suggestions: close the list first)
    Tab
    next field; at the end of a row, the next row
    ↓ ↑
    in CONTEST_ID and SUBMODE: go through the suggestions, Enter takes one
    Alt+↓
    in a date field: open the calendar
    ?
    this help (outside table cells and fields)

    The table shows the core fields (CALL, date, time, band, mode …) first; "file order" in the toolbar shows the file's order. Exports always keep the file's order.

    Fields with a fixed list in ADIF (BAND, MODE, DXCC, QSL status …) are drop-downs; the empty choice removes the field. A value is never changed by showing it. Dates are shown as YYYY-MM-DD, times as HH:MM or HH:MM:SS (UTC); the file keeps the ADIF format. Edits that were not exported make the browser ask before the tab closes.

    Checks

    Every QSO is checked against ADIF 3.1.8. The issues button lists errors, warnings and notes; "row N" goes to the QSO. After a change of language the messages of a check already made stay as they are; the next check (after an edit, or when the file is loaded again) is in the new language.

    Search & filter

    The filter bar narrows the table only: text, validation status, field conditions, source file and a QSO_DATE range. Every export still writes the whole log.

    Export

    "export .adi" and "export .adx" write a fresh ADIF file; CSV and the SOTA CSV are under the other exports. The file name is the field next to the buttons.

    Laden

    .adi- oder .adx-Dateien auf die Seite ziehen oder „Datei(en) hinzufügen…“ verwenden. Dateien kommen zum aktuellen Log dazu; „neu“ beginnt ein leeres Log, „leeren…“ entfernt das ganze Log aus dem Editor. Nichts verlässt den Browser.

    „eine Datei ↓“ speichert den ganzen Editor als eine HTML-Datei, die ohne Server und ohne Internet funktioniert.

    Bearbeiten

    Enter
    Wert übernehmen und eine Zeile nach unten
    Esc
    den Wert von vor der Änderung zurückholen (in einer Vorschlagsliste: zuerst die Liste schließen)
    Tab
    nächstes Feld; am Ende einer Zeile die nächste Zeile
    ↓ ↑
    in CONTEST_ID und SUBMODE: durch die Vorschläge gehen, Enter übernimmt einen
    Alt+↓
    in einem Datumsfeld: den Kalender öffnen
    ?
    diese Hilfe (außerhalb von Zellen und Feldern)

    Die Tabelle zeigt die Kernfelder (CALL, Datum, Zeit, Band, Mode …) zuerst; „wie in der Datei“ in der Werkzeugleiste zeigt die Reihenfolge der Datei. Exporte behalten immer die Reihenfolge der Datei.

    Felder mit fester Liste in ADIF (BAND, MODE, DXCC, QSL-Status …) sind Auswahllisten; die leere Wahl entfernt das Feld. Ein Wert ändert sich nie nur durch das Anzeigen. Daten erscheinen als JJJJ-MM-TT, Zeiten als HH:MM oder HH:MM:SS (UTC); die Datei behält das ADIF-Format. Bei Änderungen, die noch nicht exportiert sind, fragt der Browser vor dem Schließen des Tabs nach.

    Prüfung

    Jedes QSO wird gegen ADIF 3.1.8 geprüft. Der Knopf „Befunde zeigen“ listet Fehler, Warnungen und Hinweise; „Zeile N“ springt zum QSO. Nach einem Wechsel der Sprache bleiben die Meldungen einer schon erfolgten Prüfung, wie sie sind; die nächste Prüfung (nach einer Änderung oder beim erneuten Laden) ist in der neuen Sprache.

    Suche und Filter

    Die Filterleiste schränkt nur die Tabelle ein: Text, Prüfstatus, Feldbedingungen, Quelldatei und ein Bereich von QSO_DATE. Jeder Export schreibt trotzdem das ganze Log.

    Export

    „.adi exportieren“ und „.adx exportieren“ schreiben eine neue ADIF-Datei; CSV und das SOTA-CSV stehen bei den anderen Exporten. Der Dateiname ist das Feld neben den Knöpfen.
